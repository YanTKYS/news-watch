# 技術・データ仕様

収集条件・保存形式・レビュー生成・閲覧の仕様をまとめる。キー登録、実行時刻、手動フラグ、再試行・障害対応は[運用手順](operations.md)を参照。設定や処理を変更した際は、該当する文書も更新する。

## 日刊収集

実装は [collect.py](../scripts/collect.py)、設定は [config/queries.yml](../config/queries.yml)。Brave Search APIの日本向け・日本語検索を使い、直近1週間（`freshness=pw`）を検索する。保存するのはタイトル・URL・説明文などの検索結果で、記事本文は取得しない。

### 検索語と除外設定

```yaml
themes:
  - name: 自治体DX
    queries:
      - '"自治体DX"'
```

テーマ名は日刊ログの見出しになる。完全一致を意図する検索語は、例のように二重引用符を含む文字列をYAMLの単一引用符で囲む。

- 検索語は全テーマ合計10件まで。超過するとAPIを呼ぶ前に停止する。1検索語につき上位10件を1回取得し、リトライ・ページングはしない（最大10リクエスト/実行）。検索間隔を設けて呼び出す。
- `exclude_domains` はスキームなしのドメインを列挙する。サブドメインも対象で、検索語への `NOT site:` 付与と取得後の両方で除外する。
- `exclude_url_patterns` はスキームを除いたURLに含まれる文字列で除外する。ドメイン全体を除外せず転載URL等だけを対象にできる。
- 現行の除外対象は設定ファイルを正本とし、ここには一覧を複製しない。除外されたURLは `seen.json` にも記録しない。

### URLの重複排除と関連性判定

http/httpsのURLを対象とし、ホスト表記、既定ポート、末尾スラッシュ、フラグメントや既知の追跡パラメータを整理して比較する。内容に影響し得るクエリパラメータは保持する。同一URLは既知データと照合し、同一実行内で複数検索語にヒットした場合は1件にまとめて `Queries:` を統合する。

Jev（System One）は、除外・既知URLの排除を通過した新規候補だけを関連性判定する。タイトル・説明文・検索語を送り、記事本文は取得しない。

| 項目 | 挙動 |
| --- | --- |
| 判定 | 「日本の自治体DX・生成AI活用に関係する記事か」のYes確率が0.30未満なら除外 |
| 上限 | 1実行あたり最大20回、リトライなし |
| 未設定・障害・上限到達 | 候補を除外せず保存し、収集継続 |
| 非関連URL | `data/jev-rejected.json` に記録し、7日間再判定しない。`seen.json` には記録しない |

Jev未設定時は非関連キャッシュも使わない。期限切れキャッシュの整理は新たな非関連URLを書き込む際に行う。

### 同一話題候補の観測

[topic_dedup.py](../scripts/topic_dedup.py) が、新規候補同士と取得日基準で直近7日間の保存済み記事をタイトルから比較し、同じ発表・転載の候補をActionsログの `Topic duplicate candidates` / `Topic duplicate pairs` に表示する。**観測のみで、記事を削除・非表示にしない。** 閾値や曖昧な候補を避ける条件は実装を正本とし、定数の一覧はここへ転記しない。

## 保存形式と派生データ

| パス | 内容・更新元 |
| --- | --- |
| `logs/YYYY/YYYY-MM.md` | 日刊の正本。収集処理が日付→テーマ→記事の順に追記 |
| `data/seen.json` | 収集済みURLと初回取得日。同じURLの再記録を防ぐ |
| `data/jev-rejected.json` | Jevの非関連判定キャッシュ |
| `data/months.json` | 日刊の月一覧。新着保存時に `logs/` から更新 |
| `data/search-index.json` | 日刊の全期間検索用。[search_index.py](../scripts/search_index.py) で再生成可能 |
| `reviews/weekly/YYYY-Www.md` | 週刊レビュー。ISO 8601の週番号で、年末年始は暦年と異なる場合がある |
| `data/weeks.json` | 週刊の号と対象期間の一覧 |
| `reviews/monthly/YYYY-MM.md` | 月刊レビュー |
| `data/review-months.json` | 月刊の号と対象期間の一覧。日刊用の `months.json` とは別 |

日刊の記事には `URL`、`Source`、`Queries`、`Published`、`Retrieved` と説明文を保存する。`Published` はAPIから公開日を得られた場合のみ記載する。レビューの期間選択・検索の並び順は取得日（`Retrieved`）を基準とし、公開日や出来事の発生日とは区別する。

検索インデックスは、タイトル・URL・情報源・公開日・取得日・テーマ・説明文を含むJSON配列。同じURLは1件だけとし、http/https以外のURLは含めない。日刊ログから再構築できる派生データで、生成日時は埋め込まず、内容が変わる場合だけ書き込む。収集ワークフローが別ステップで更新し、このステップの失敗でも日刊のcommitは継続する。復旧は[運用手順](operations.md#検索インデックスの再生成)を参照。

## 週刊・月刊レビュー

実装は [weekly.py](../scripts/weekly.py) と [monthly.py](../scripts/monthly.py)。本番はGeminiの `generateContent` を使い、月刊も週刊のAPI呼び出し・モデル設定を共用する。Brave/Jevの再検索、Google検索等のツール利用、元記事本文の取得は行わない。定期・手動の対象選択や欠号補完は[運用手順](operations.md#週刊の対象指定と欠号補完)を参照。

### 入力の選別

| 項目 | 週刊 | 月刊 |
| --- | --- | --- |
| 記事の対象 | 対象週の月曜〜日曜に取得 | 対象月に取得 |
| 記事上限 | 50件 | 150件 |
| 説明文 | 500文字まで | 300文字まで |
| 上限超過時 | 日付×テーマの偏りを抑え、同一話題候補を後回しに選別 | 週刊の出典記事を優先して選別 |
| 週刊からの補助情報 | なし | 対象月に重なる週の注目トピック。概況・まとめは送らない |

各記事に `article-001` 形式のIDを付け、タイトル・テーマ・情報源・公開日・取得日・説明文を送る。URL・検索語・月別ログ全体は送らない。選別による未入力件数をログに表示し、元の日刊記事は削除しない。同一話題候補は `related_ids` によりAIへ伝えるだけで、自動統合しない。

月刊に渡す週刊トピックは、その出典すべてが対象月の日刊記事に対応するものに限る。月またぎの対象月外の記事に基づく内容を混ぜず、利用できる週刊がない場合は日刊ログだけで生成する。

### 構造と検証

- 週刊は「今週の概況／注目トピック（1〜5件）／今週のまとめ」。月刊は「今月の総括／主要トレンド（1〜6件）／翌月以降の注目点」。各トピックには見出し、説明、自治体実務への示唆、出典を含める。
- `responseJsonSchema` によるJSONの構造化出力をPythonで再検証する。必須項目・型・文字数・件数、本文にURLを含まないこと、出典IDが入力に属し重複しないことなどを検証する。詳細な文字数・Schemaの定義は各スクリプトを正本とする。
- 候補なし、安全性ブロック、`finishReason` が `STOP` 以外、不正JSON、内容検証失敗は保存せず実行失敗にする。自動修復・別モデルへの切り替えはしない。
- 思考上限は2048トークン、出力上限は16384トークン。思考トークンも出力上限に含まれるため分けて指定する。APIの回数・タイムアウト・再試行条件は[運用手順](operations.md#apiの再試行方針)を参照。
- 出典リンクはAIが書いたURLを使わず、検証済みIDからPythonで元記事のhttp/https URLを付与する。出力にはAI生成の注記、モデル、元記事数・入力件数、生成日を残す。

レビュー生成は日刊ログ・`seen.json` を読み取るだけで変更しない。出力Markdownと対応するレビュー一覧JSONを更新する。構造・出典検証は記述内容の事実確認を代替するものではない。

## 閲覧と検索

[index.html](../index.html)、[app.js](../app.js)、[parser.js](../parser.js)、[style.css](../style.css) による静的サイト。日刊は一覧JSONから月を選び、元のMarkdownをカード表示する。週刊・月刊も一覧から号を選び、Markdownを1カラムの記事として表示する。

日刊検索は初回検索時にインデックスを1回読み込み、ブラウザ内で絞り込む。外部検索サービス・APIは使わない。対象はタイトル・説明文・テーマ・情報源で、部分一致・空白区切りのAND検索。NFKC正規化と小文字化で全角/半角や英字の大文字/小文字をそろえる。

検索中は月選択・並び替えを無効にし、全期間から取得日の新しい順に50件ずつ表示する。「さらに表示」で追加し、検索欄を空にすると選択月の通常表示へ戻る。週刊・月刊の本文は検索対象に含めない。

外部由来のテキストは `textContent` で描画し、リンク先はhttp/httpsを検証する。表示用に外部文字列を `innerHTML` へ渡さない。公開設定とローカルでの確認方法は[運用手順](operations.md#github-pagesとローカル配信)にまとめる。
